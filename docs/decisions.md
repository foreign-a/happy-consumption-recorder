# 1.1 规格解释与决策

依据：用户提供的 `happy_comsumption_recorder.md` 及本次答复。业务金额继续使用整数分，Room 数据库版本和 1.0.0 凭据格式保持不变。

| 项目 | 解释 / 决策 | 依据 |
| --- | --- | --- |
| 过去30天范围 | 从当前账户已有最早日期的前一天向前连续30天，不包含最早日期；每次再次点击继续向前30天。没有记录时以今天为锚点。事务内查询与写入，不清零或覆盖已有记录 | “相对于已有记录的最早天数”的解释，保障旧记录 |
| 生成记录类型 | 一键批量生成全部为零、自动记录；保留单条手工补记入口 | 文档同时要求批量归零和单条新增留空归零 |
| 编辑 | 点击修改直接打开空白输入框，留空维持原值，显式输入0才归零；保存时保留最终确认，取消任一步不写入 | 1.1 第2、3项 |
| 新增 | 留空（含纯空白）按0处理；非空输入继续执行原金额范围和两位小数校验 | 1.1 第3项 |
| 币种 | 暂按每个账户选择人民币 / 美元 / 英镑显示单位；不进行汇率转换，不改金额或日期，不依赖界面语言；旧账户默认人民币 | 已向用户询问账户级或记录级；等待补充答复时采用账户级解释并显式告知 |
| 卸载与重装 | 增加卸载前导出、重装后导入备份；覆盖升级直接保留本地数据。1.0.0 需先覆盖升级到1.1并导出，无法在原1.0.0卸载后凭空恢复 | 用户明确选择“增加导出/导入备份…同时保证覆盖升级保留数据”；Android 卸载会删除私有数据 |
| 备份范围与文件 | 保持账户隔离，登录后导出当前账户的凭据（仅盐与散列）、记录、币种；多个账户分别导出；登录页也可导入 | 避免一个账户访问另一个账户的数据，不备份会话与诊断日志 |
| 备份保护 | 独立的至少8字符备份密码、AES-256-GCM、随机salt/IV与PBKDF2-HMAC-SHA256；通过系统文件选择器保存到应用外，不新增网络或广泛存储权限 | 备份含账户及消费信息，防止明文泄露；密码与文件均不写日志 |
| 恢复冲突与中断 | 导入前完整校验；同名账户拒绝整个导入；新账户重新映射内部ID，保留日期、金额、类型、更新时间、原登录密码与币种；持久化导入计划支持中断恢复 | 保护已有账户与记录，处理新旧主键冲突 |
| 备份格式及限制 | 加密文件 `.hcrbackup`，格式版本1，最大64MB；无效或超限文件不导入，错误密码或篡改拒绝 | 避免对无效输入进行无界读取；后续版本可据格式版本兼容升级 |
| 发布版本 | versionName=1.1、versionCode=2、沿用1.0.0证书；Release附件命名 `app-release_1.1.apk` | 用户文件名要求与覆盖升级签名要求 |

## 1.2 点按金额与逐项币种（2026-10-17）

依据：用户本次明确要求替换主界面修改流程，并允许每项金额使用不同币种；此要求覆盖1.1中账户统一显示币种和修改保存二次确认的行为。

| 项目 | 决策与解释 |
| --- | --- |
| 点按编辑 | 主界面的早餐、午餐、晚餐、其他四项金额均可直接点按。使用应用内电话式三列数字键盘，支持小数点、退格；不依赖设备输入法是否提供小数键。金额输入从空白替换缓冲开始，留空保持原值 |
| 确认 | 原修改按钮替换成确认按钮；点确认直接保存该日期的待改金额与币种，不再额外弹确认框。键盘区也提供同一确认操作，便于小屏或横屏使用 |
| 未确认离开 | 有实际未保存更改时，点击编辑区以外、滚动列表或返回会询问保存、放弃或继续编辑。拦截的普通页面操作须处理草稿后再次点击；切换另一条记录的金额则在处理草稿后进入目标金额。无实际修改时关闭键盘，不制造空确认 |
| 系统离开 | 不拦截Android主页或其他应用的系统操作；进程存活期间草稿由ViewModel保留，旋转和页面重建不自动写入。强行终止进程不会把未确认数据写入数据库 |
| 逐项币种 | 每个日期的四项金额各自保存人民币、美元或英镑。主界面键盘为当前金额选择币种；新增记录也能逐项选择。币种变更属于草稿，确认才写入 |
| 混合合计 | 按币种分别汇总，例如三餐合计¥9、其他$5显示为“¥9.00 + $5.00”；不引入汇率、不把不同币种的数字相加。编辑中的单项显示草稿，顶部合计在保存后更新 |
| 旧币种设置 | 改为新金额的默认币种，不再修改历史记录。升级时把1.1账户原显示币种固化到已有四项金额，1.0账户默认人民币，避免旧金额被重新标注 |
| 数据兼容 | Room版本1→2仅追加四个币种列；原主键、账户、日期、整数分、记录类型及更新时间保留。注册和登录凭据格式不变，正式预览包沿用原证书 |
| 备份兼容 | 新备份文档版本2携带四项币种，继续读取1.1版本1备份并按其账户币种恢复。旧1.1不会读入新格式，避免静默丢失逐项币种 |
| 交付范围 | 使用1.2/versionCode=3生成本地验收包；本次请求为功能修改，先完成实现和测试供用户验收 |


## 1.2 日期导航与用户页（2026-10-17）
- 本轮接续尚未发布的 1.2 本地验收版，保留 versionName=1.2、versionCode=3；未获得本轮发布指令，不自动上传 GitHub。
- “最近一个星期”解释为含今天的连续七天（今天往前六天），跨月仍连续。展开后显示当前月，周一作为一周开始，可向前翻月，最晚为当前月份；收起回到最近七天。
- 只有当前账号存在记录的日期可跳转；空日期和未来日期为灰色且不可点击，不创建空记录。月历查询失败明确显示错误和重试，不把未知日期假装成无记录。
- 点击日期定位到对应卡片并以边框标识；超过当前分页的旧记录先按日期位置补充所需页，再定位。仅查询月范围日期元数据，不提前加载全部账目。
- 首页和用户页为底部两个入口。备份/恢复、登出、删除用户、语言及主币种入口迁移至用户页；登录页恢复入口保留，以支持重装后尚未登录时恢复。
- 主币种继续作为新增记录的默认币种，不重写既有逐项币种。删除用户仍须验证当前密码。
- 切换页签及选择日期前先处理未确认金额；保存成功或放弃后完成原请求，继续编辑则停留首页。编辑时月历暂缩为最近七天，为数字键盘留出空间。首页滚动、已加载页和展开月份在页签往返及语言重建时保留。
- 日期栏与底部导航加入后，单条补记改为与批量生成同行的按钮，防止原悬浮按钮遮挡记录的删除操作；编辑时确认置于当前卡片顶部，键盘内确认保留。
- 编辑时卡片用紧凑的四项金额横排保留切换入口；窄高度横屏将顶部区域设为可滚动区域，为列表与键盘留出空间。
